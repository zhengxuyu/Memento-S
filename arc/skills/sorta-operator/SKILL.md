# The Sorta Operator

Many concepts have fuzzy boundaries — things can "sorta" have a property without fully having it. The sorta operator lets you use a concept productively while flagging that it's an approximation, not a literal claim. This prevents both over-claiming and under-claiming.

## When to Apply
- A system exhibits behavior that resembles X but isn't a textbook case of X
- You need to describe something in between two categories
- Precision would be misleading but outright denial would lose useful information

## Procedure
1. Identify the concept you want to apply (e.g., "knows," "wants," "believes")
2. Ask: does this thing literally have this property, or does it sorta have it?
3. If sorta, use the concept with the explicit qualifier
4. Explain what the approximation captures and what it misses
5. Check if the sorta-version is doing real explanatory work or just hand-waving

## Example
A thermostat "sorta believes" the room is too cold. It doesn't literally believe anything, but saying it has no relevant internal states throws away useful information. The sorta operator lets us say the thermostat has a belief-like state — one that tracks temperature and drives action — without claiming it's conscious.

## Anti-Pattern
Don't use "sorta" to dodge hard questions. If the approximation does zero explanatory work, drop it. "Sorta" is a precision tool, not an escape hatch.
