# Daddy Is a Doctor

A child who says "Daddy is a doctor" when daddy is actually a plumber reveals something important: the child has learned the *category* of professions and the *grammar* of attribution, but not the specific mapping. The error is systematic, not random — and it shows genuine (partial) understanding.

## When to Apply
- An agent makes errors that show partial understanding of a system
- Distinguishing productive mistakes (partial learning) from random flailing
- Building up understanding incrementally — recognizing what's been learned
- Evaluating whether a wrong hypothesis was at least in the right category

## Procedure
1. Examine the error or wrong hypothesis
2. Ask: what does this error *correctly* understand? (category, structure, relationship type)
3. Ask: what specifically is wrong? (specific instance, mapping, value)
4. Use the correctly-understood part as a foundation for the next attempt
5. Focus correction on the specific wrong element, not the whole framework

## Example
Agent hypothesis: "Color 5 is the goal." Actual goal: color 12. The agent correctly identified that a specific color marks the goal (structural understanding) but got the specific color wrong (instance error). Fix: keep the framework, update the color mapping.

## Anti-Pattern
Don't treat every error as showing partial understanding. Some errors are genuinely random. This tool applies when errors have a *pattern* that reveals systematic (mis)understanding.
