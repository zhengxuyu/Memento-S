# What Is It Like to Be a Bat?

From Thomas Nagel's famous question: even a complete functional description of a bat's sonar system may not tell us what it is *like* to be a bat. This tool reminds us that third-person descriptions (behavior, function, mechanism) may not exhaust first-person perspectives — and to be careful about assuming they do.

## When to Apply
- Modeling what another agent (or system) "knows" or "perceives"
- Functional description of a system seems complete but something feels missing
- Deciding whether behavioral equivalence implies equivalent understanding
- Distinguishing between processing information and comprehending it

## Procedure
1. Describe the system's behavior and function from the outside
2. Ask: does this external description capture everything relevant?
3. Identify any aspects that seem to require an "insider" perspective
4. Consider whether the gap matters for your current task (sometimes it doesn't)
5. If it matters, flag it as a limitation of your model

## Example
An agent observes that an NPC moves toward food when hungry. Functional description: "NPC seeks food when energy is low." But does the NPC have a "goal" or just a reflex? For prediction, it may not matter. For understanding the game's deeper mechanics, the distinction could be crucial.

## Anti-Pattern
Don't use this to claim that nothing can ever be understood from the outside. Functional descriptions are enormously useful. This tool flags specific cases where they might be insufficient, not a general skepticism about external observation.
