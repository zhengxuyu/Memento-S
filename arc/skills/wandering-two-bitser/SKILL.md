# The Wandering Two-Bitser

A device built to detect US quarters is taken to Panama, where it accepts their coins too. Is it now a Panamanian-coin detector? Structurally identical behavior, but the function depends on design history and context. What something does is not the same as what it's for.

## When to Apply
- Debating what a system's states "represent" or what it's "for"
- A structure could serve multiple functions depending on context
- Determining whether two structurally identical systems have the same function

## Procedure
1. Describe the system's current behavior (what it does)
2. Identify its design history (what it was made/evolved to do)
3. Identify its current context (what environment it operates in)
4. Ask: does function follow from structure alone, or does history matter?
5. Determine function based on the combination of history, structure, and context

## Example
A heart pumps blood and makes thumping sounds. Its function is pumping blood (that's what selection designed it for), not making sounds — even though it reliably does both. Structure alone can't tell you which output is the function and which is a side effect.

## Anti-Pattern
Don't insist that function is only determined by history. Sometimes redeployment in a new context genuinely creates a new function. The point is that structure alone is insufficient.
